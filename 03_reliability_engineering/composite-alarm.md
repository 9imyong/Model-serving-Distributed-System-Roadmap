# Composite Alarm 전략

## 1. 증상과 원인 후보를 연결한다

복합 알람은 여러 신호를 AND/OR로 묶어 상황을 좁히는 방법이다. 모든 알람에 AND 조건을 늘리면 실제 장애를 놓칠 수 있다. 사용자 영향 알람은 독립적으로 유지하고, 복합 조건은 원인 분류와 대응 경로 선택에 사용한다.

## 2. OCR 진단 예시

| 조건 조합 | 원인 후보 | 다음 확인 |
|---|---|---|
| 대기 나이 증가 AND GPU 활성도 높음 | 추론 처리량 부족 | batch별 처리량, 큰 입력 비율 |
| lag 증가 AND GPU 활성도 낮음 | 입력 다운로드·CPU·Worker 정지 | 단계별 시간, heartbeat |
| 결과 토픽 lag 증가 AND DB 지연 증가 | Writer/DB 병목 | 연결 풀, 잠금, 쓰기 IOPS |
| OOM 증가 AND 재시도 증가 | 큰 입력 또는 과도한 동시 실행 | 입력 shape, batch, 모델 복제 수 |

상관관계는 원인 확정이 아니다. GPU 활성도가 높아도 유효 작업 처리량이 낮을 수 있다.

## 3. 시간 조건과 결측값

```text
사용자 영향 = deadline 초과율이 허용 범위를 넘음
추론 병목 후보 = 대기 나이 상승 AND GPU 부하 지속
저장 병목 후보 = 결과 대기 나이 상승 AND DB 지연 지속
호출 = 사용자 영향 OR 처리 진행이 멈춘 장기 적체
```

지속 시간, 평가 주기, 해제 기준을 명시한다. 발동과 해제 임계값에 차이를 두는 hysteresis는 알람이 반복해서 켜지고 꺼지는 현상을 줄인다. 유지보수 억제에는 종료 시간을 둔다.

메트릭이 없다는 이유로 정상으로 간주하지 않는다. 수집기와 Worker heartbeat 부재를 별도 감지하고, 트래픽이 없는 정상 상황과 구분한다.

## 4. 검증

GPU 지표 수집을 중단해도 사용자 영향 알람이 살아 있는지 확인한다. DB 장애 때 GPU 증설을 제안하지 않는지, 회복 시 알람이 안정적으로 해제되는지도 확인한다.
