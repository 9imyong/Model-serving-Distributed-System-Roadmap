# ADR-001: 작업 상태 보호와 멱등 처리

- 상태: 제안 — 학습용 설계이며 운영 검증 전
- 범위: Kafka 기반 OCR의 작업 획득과 결과 확정

## 배경

Worker 재시작과 네트워크 오류로 같은 job이 여러 번 실행될 수 있다. 지켜야 할 규칙은 성공 결과의 존재, 오래된 Worker의 쓰기 차단, 동일 요청의 중복 효과 방지다. 결제 시스템인지 여부만으로 정합성 요구를 낮추지는 않는다.

Strong consistency와 idempotency는 양자택일이 아니다. 전자는 관찰 순서, 후자는 반복 요청의 효과를 다룬다.

## 선택지

| 선택 | 이점 | 비용·제약 |
|---|---|---|
| 전체 경로를 분산 트랜잭션으로 묶기 | 넓은 원자성 경계 추구 | GPU·객체 저장소까지 참여시키기 어려움 |
| DB의 짧은 원자적 전이 + 멱등 처리 | 경계가 명확하고 재시도 가능 | lease·중복 제거·복구 설계 필요 |
| 중복 보호 없이 마지막 쓰기 채택 | 구현 단순 | 오래된 결과 덮어쓰기와 상태 역행 |

## 제안 결정

두 번째 방식을 기본안으로 한다. 권위 있는 DB에서 작업 획득과 최종 결과 확정을 보호한다. attempt token으로 소유권을 확인하고, 결과와 성공 상태를 한 트랜잭션에서 확정한다. 조회 캐시·통계는 지연을 허용하고 원본으로 재구축할 수 있게 한다.

이 결정은 DB 조건부 업데이트가 모든 복제본의 강한 읽기를 보장한다는 뜻은 아니다. 완료 직후 조회 보장은 별도 읽기 경로로 구현한다.

## 결과와 수용 비용

중복 추론 비용은 남는다. lease 스캐너, outbox Relay, 고아 파일 정리를 운영해야 한다. 대신 저장과 전달 사이의 실패를 추적하고 복구할 수 있다.

## 검증·재검토 조건

동시 획득, 저장 후 종료, lease 만료 후 늦은 완료를 주입해 불변식을 확인한다. 여러 job에 걸친 원자적 제약이나 지역 간 즉시 읽기 요구가 생기면 트랜잭션·복제 설계를 재검토한다.
